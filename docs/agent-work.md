# agent-work 是什麼

Agent 寫程式時會用到兩類東西，不要混在同一個 git 裡：

| | 放哪 | 例子 |
|---|---|---|
| 怎麼做事 | skill 庫（本套件） | 訪談、寫 spec、TDD、納管 |
| 這個專案此刻的工作 | **agent-work**（你自己的工作區） | 地圖、領域補充、當次 spec、票 |

**agent-work** 就是那份工作區：每個專案一個資料夾，跟業務 git 分開。

「納管」= 讓目前這個 git 開始使用這份工作區。不是加入某個 GitHub 組織。

## 為什麼要分開

公司專案通常不能把你的私人筆記、本機路徑、當次任務稿 commit 進去。  
那些內容如果只躺在另一棵樹上、Agent 又不知道去讀，開著公司 repo 寫 code 時就等於沒放。

所以規則是：

- 私人內容不進公司 git。
- 開著公司專案時，靠你本機工具設定裡的一條規則去讀工作區裡對應的地圖。公司 git 裡不必放指標檔。
- 你自己的專案可以把薄入口（例如 `AGENTS.md`）放進該 git；詳細文件放該 repo 的 `docs/`。

Skill 給任何人裝；工作區是你自己的，路徑寫在本機設定，不寫進 skill 庫。

## 五層（範圍，不是五份百科）

先拿地圖，再按任務讀細節。

1. **全域習慣** — 對所有專案都成立（語言、git、回答方式）。
2. **索引** — 已經納管哪些專案；不要每次把整棵工作區灌進對話。
3. **跨專案手冊** — 只對「公司」或只對「個人」成立的習慣。不能蓋過團隊已經寫進該 repo 的規範。
4. **專案地圖** — 這個 repo 的文件怎麼找。公司：只在工作區。個人：主要在該 git。
5. **當次任務** — 這張票的 spec／tickets。

公司補充不能蓋過該 repo 裡團隊已有的入口。

## 工作區長什麼樣子

```text
工作區/
├── 全域習慣
├── 索引
├── work/<專案名>/          ← 公司：地圖 + 補充 + 當次任務
└── personal/<專案名>/     ← 個人：任務／spec（專案地圖在該 git）
```

`<專案名>` 與 git 根目錄的資料夾名相同。
