# 實作 Playbooks

按任務選一種主要路徑；共同的 repo、ownership、授權與回報規則仍以 [SKILL.md](../SKILL.md) 為準。

## 新功能

1. 將 TaskBrief／TaskContract 的 acceptance 拆成可觀察結果，先完成最小端到端切片。
2. 找出既有入口、資料模型、元件與錯誤處理慣例，沿既有邊界實作；只有契約明定才新增 schema 或持久化行為。
3. 檢查空資料、錯誤、取消／重試、重複操作、權限和副作用中與本需求相關的情況。
4. 交代每項 acceptance 的程式位置、尚待 verify 的真實操作與回歸範圍。

## BUG 修復

1. 固定失敗版本、前置條件、輸入／資料、使用者操作與可觀察錯誤。區分已重現、靜態推論與未知；不能重現就不編造行為證據。
2. 沿失敗路徑追根因，記錄證據如何支持或排除假設。重大未知先回報，不用猜測擴大修正。
3. 以最小變更修根因，不只遮蔽症狀；加入能抓住原失敗的檢查。
4. 由 `verify-change` 對同一入口／條件重跑修前失敗路徑，並檢查必要回歸。環境不足時保持 blocked 或 partial。

## 重構

1. 列出必須保留的公開輸入、輸出、錯誤、資料副作用、相容性及已知呼叫者。
2. 用 characterization tests 或現有行為證據固定邊界；不為追求測試數量測試無關內部細節。
3. 小步替換實作，逐步維持同一外部行為。需要改行為時先回到需求／Plan 取得批准，另列 acceptance。
4. 驗證新舊呼叫路徑、相容性與必要效能／資料限制；報告尚未覆蓋的呼叫者。
