# 地圖查找、歸屬與規模

## 查找

- 優先追明確設定或產品／工作區文件的指標；都沒有時查產品 `docs/feature-map/README.md`，及已確認對應的工作區 `work/<project>/feature-map/README.md` 或 `personal/<project>/feature-map/README.md`。工作區根可從已載入的 Agent Work bridge 或實際生效的 Omni Skills 設定 `workspaceRoot` 找到（沿用已知的 `--config`／`OMNI_CONFIG`，預設 `~/.config/omni-skills/config.json`）；以根索引、專案 README 與來源 repo 身分交叉核對，不靠猜家目錄或掃其他專案。沒有工作區也能獨立執行。
- 同時查實際專案 README、文件索引、既有 `features/README.md` 及可確認的舊功能索引與驗收入口。指向同一正文的連結不是第二份地圖；只列專案、路由或計畫的索引不等於已驗證的功能地圖。
- 同一範圍有兩份不同正文且未指定主檔時，記錄兩個位置及差異。唯讀工作只引用來源明確的部分並獨立查證重疊範圍；正式更新停在衝突範圍，直到來源釐清。
- 找到與本次範圍無關的舊地圖，不代表本範圍已知。例如報告中心兩條紀錄不代表 Reader 已盤點。來源無法讀取是「未知」，不是「確認沒有」。

## 寫在哪

- 既有、適用且未被要求移動的地圖，若已獲文件修改授權，就在原位置局部維護。
- 新正式地圖讓使用者選：已對應的 Agent Work 專案層 `<project>/feature-map/`，或該產品 repo 的 `docs/feature-map/`。若一開始已指定且符合團隊規則，直接使用。不為補一張地圖自動納管專案。未選或未授權寫入時，交付預覽與候選位置，而不是擅自建立正式檔。
- 同範圍只有一份正文。經批准遷移時，在舊入口保留指向新位置的連結，不能兩邊同步複製。只編寫本次授權文件，不更動產品行為、資料、測試或 Git 歷史。

## 規模與覆蓋

小案從 `README.md` 開始；內容變大時按產品能力拆分，例如 `areas/reader/library.md` 和 `areas/reader/reading.md`。根索引保留範圍、產品 revision、覆蓋缺口、各區及 ID 入口；局部更新時逐區／逐條保留其實際證據 revision，不用索引的更新日期覆蓋。只有跨區流程值得獨立維護時才加 `journeys/`，按順序引用 feature ID，不抄各區正文。ID 不與路由或文件路徑綁定，不重用已退役 ID。

暫時地圖可只列本次稽核相關的目標、入口、角色、主要狀態、來源、未知與副作用；清楚標 `partial` 及「暫時／非正式」，不宣稱這是完整契約或產品驗收。
