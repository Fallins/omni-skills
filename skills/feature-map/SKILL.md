# FeatureMap

地圖描述目前產品提供什麼、從哪裡進入及如何確認，不是路線圖、決策台帳、迭代紀錄或驗收結果。可以獨立使用；不要求先跑 UI 稽核。全程遵守專案規則和本次授權。

1. **定範圍與版本**：確認產品 repo、完整 commit、dirty/patch 狀態、功能範圍、識別角色與入口。不能只用 CWD 名稱辨識 worktree 或同名專案。跨 repo 時標明各自來源。預設只盤點請求的功能，不用文件數量推論全覆蓋。
2. **先找現有地圖**：依[查找與寫入規則](references/storage.md)辨別同一來源的指標、舊版或各自涵蓋不同範圍的地圖。唯讀盤點仍可繼續；來源衝突時不覆寫、不搬移，報告衝突與影響。
3. **由入口對證據**：讀適用規則、使用說明、實際入口、權限、資料副作用與既有驗證。逐項區分實際觀察、靜態確認、推論和未知。未探索區域記為未盤點，不能當成功能不存在。適用於 UI、公開 API、正式 CLI 或可從事件／操作觀察的背景功能。
4. **輸出／更新**：完整功能條目依同一安裝來源的 [verify-change FeatureMap 契約](../verify-change/references/feature-map.md)；不另定 schema。契約不可讀時可交付明確標為未對齊契約的暫時盤點，不宣稱合規或落正式版。保留既有 ID、驗證收據與有效指標；刪除／替代功能留下可追溯的退役指標。缺資料明列缺口，不填假值。輸出摘要列出位置、範圍、基線、證據類型及未確認項。

盤點預設讀取文件、程式與既有證據，不啟動站點、不呼叫產品入口。需要新實測時須先確認本次已授權、適用環境與可接受副作用；不能證明安全時只回報限制。整理地圖不會自動啟動驗收、實作、派工或發布。沒有適用收據就標 `not-run` 或 `blocked`，而不是 `passed`。若有歷史收據，保留並標它的版本／環境；不要當作目前版本結果。若呼叫方要求快速稽核且未授權落檔，只回傳當次範圍的暫時地圖，可放在已授權報告內或對話中；不建立正式地圖。
