# 任務理解

先讀取本次任務可取得且相關的資料，再決定是否需要詢問使用者。用於新需求、既有功能調整、BUG、程式審查或使用者要求先釐清方向；簡單問題若上下文已足夠就直接回答，不強迫跑流程。

## 行為

1. 保留使用者明確提出的目標、限制、授權與已確認決定，不重問已回答事項。
2. 查閱任務直接相關的 repo 指引、文件、程式入口、測試或既有設計；把目前程式實際行為與需求文字分開記錄。只查足以理解本次任務的來源，不做無界全庫掃描。
3. 分開標示 verified、assumed、unknown、contradicted；重要結論記錄檔案／符號、版本或 commit，以及查核方法。沒有執行的命令不能寫成通過。
4. 明確整理目標使用者與情境、預期結果、範圍與非範圍、不能破壞的既有行為、限制，以及尚未解決的決策。
5. 區分 operation mode：read、plan-only、execute、review。大型或高風險不會自動把 plan-only 變成 execute；任務複雜度也不代表需要多代理。
6. 若資訊可從核准可讀的來源查明，先查再問。只有影響產品行為、範圍、驗收、跨任務契約或必要授權的未知，才整理具體問題與受阻範圍。

## 輸出：TaskBrief

依需要使用短段落或下列欄位，不要求為小任務另存檔：

- task_id：已存在的票號／識別碼；沒有時可省略，不捏造。
- mode：read、plan-only、execute 或 review，並註明來源是使用者明示或目前判讀。
- goal、scope、out_of_scope。
- acceptance：可觀察的成功條件。
- source_refs：實際查閱的來源與版本。
- constraints：repo／環境、相容性、資料、安全及其他適用限制。
- open_decisions：問題、受影響範圍、目前證據及解除條件；沒有則明示無阻塞決策。

若目前證據不足以安全前進，交付已確認部分並精確指出缺少什麼、會阻塞哪個後續步驟。沒有未知時，不為了填欄位而提出問題。

## 完成界線

任務目標、邊界、成功條件和重要未知已足以支援下一步，或阻塞範圍已說清楚，即完成理解階段。需要整體研究與拆解時交由 plan-change；本技能不產生大型 DAG、不派工、不修改產品，也不把假設包裝成規格。
