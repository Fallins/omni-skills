# 報告格式

1. **範圍與判斷依據**：產品 revision、部署是否對版、帳戶角色／裝置／環境、採用的規範與版本、地圖來源與覆蓋。沒有地圖時列暫時盤點及是 sibling 還是 fallback。記錄安全限制及實際允許的副作用。
2. **覆蓋矩陣**：功能 ID（或暫時標籤）→ 目標／畫面 → 情境與重要狀態 → 目標裝置及方法 → 證據、檢查結果或沒看原因。方法分「實測」「模擬」「靜態」「未驗證」「不適用」，逐項寫明覆蓋，不能把前兩者混為一談。另附 UI 橫向比較，列同類元件／狀態在各頁的實渲染與來源差異。
3. **發現**：每項記 ID、UI／UX 或兩者、情境與版本、實際／預期、重現步驟、證據（截圖、操作結果或具體檔案位置）、建議與預估影響範圍。分「明確違反」「可觀察的障礙」「建議」，未有證據的疑點列待驗。以使用者影響評級：P0 資料風險或核心流程卡死無替代；P1 明顯阻礙、容易誤操作或要繞路；P2 局部不一致／次要摩擦；P3 打磨。證據強度和嚴重度分開；同一共因合併但記錄受影響處。脫敏後再附畫面或日誌。
4. **後續**：優先列可依序處理的前 3–5 項（不足就照實列），說明怎麼驗收、哪些要設計審核、哪些需要隔離資料或真機。報告不等於已批准實作。
