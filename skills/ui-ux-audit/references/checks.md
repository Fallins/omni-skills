# 稽核準則：固定方法，按產品選題

先列明接受的專案規範、設計文件／token、適用的外部標準與版本或查閱日期。專案約定、平台慣例、法規／承諾、啟發式建議要分開；明示衝突而不是自己宣布改規則。必要時查 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[Nielsen 的可用性啟發式](https://www.nngroup.com/articles/ten-usability-heuristics/)或目標平台指引。若沒查到合適來源就標明，不憑記憶宣布合規。不要預設固定 px、視窗寬度、圓角、風格或必查的主題數。

## UI：同類畫面與狀態比較

- 依產品實際使用的元件抽樣：橫跨代表畫面比較相同目的的按鈕、提示／通知、彈窗、表單、清單及導航。核對元件來源、共用 variant、token 或主題映射。看起來一樣不代表重用；重用不代表外觀一致。合理的差異（如破壞性操作、裝置或元件意圖不同）保留理由。
- 對照畫面實渲染與規範：色彩／對比、文字大小與層級、間距、彈窗尺寸與溢位、圖示、觸控目標、焦點、亮暗／主題的狀態。必要時截圖並讀 computed styles／元件來源；只能讀碼時不宣稱視覺實測。抽查鍵盤、文字放大、重排、safe area、可讀名稱／角色／狀態與動態訊息，依實際平台做，非合規認證。
- 沒有可視介面的模組，UI 軸標不適用；CLI／API 等可以依操作人的任務檢查可探索性、結果回饋和復原。

## UX：使用者能否可靠完成任務

- 用角色與具體目標定義入口、步驟、成功訊號和下一步。看找到功能、辨別狀態、回饋時機、返回後是否保有脈絡、錯誤是否說明可做什麼、是否隱含高成本或重複動作。
- 依業務風險抽樣正常、初次／空、載入／長等待、錯誤、權限不足、部分成功、中斷／返回、重試、取消、破壞性操作與衝突；離線、重連、前後台切換只在產品有關時納入。能看到成功訊息不代表資料生效，能找到按鈕也不代表完整走通。
- 效能可量時記裝置、版本、網路條件及觀察指標；否則只記可觀察到的等待／卡頓，不造數字。桌面縮窄或裝置模擬不能代表真機、PWA 或電子紙驗收。
- 可讀性是閱讀器核心；長工作回饋與恢復是任務型工具核心。不要把任一產品的取樣全部複製到另一產品。
